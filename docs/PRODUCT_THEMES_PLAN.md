## เป้าหมาย

เจ้าของแก้หน้าเว็บที่ออนไลน์อยู่และสร้างรุ่นใหม่ได้ด้วยตัวเอง แต่ละรุ่นมีบุคลิกของตัวเอง
และใช้วิธีเลือกไซส์/ซื้อสินค้าเดียวกัน: แก้ไข → พรีวิว → บันทึกร่าง → ยืนยันเผยแพร่
Admin ใช้สไตล์ทำงานเบจ/กระจกฝ้าที่ตกลงแล้ว ส่วนหน้าสินค้าใช้ธีมของแต่ละรุ่น

ย่อข้อความสนับสนุนหรือเปลี่ยนลำดับภาพ โดยยังเห็นชื่อ ราคา และทางไปเลือกไซส์ชัดเจน
การตรวจครั้งนี้เป็นเรื่องดีไซน์/โครงเนื้อหา ไม่รับรอง checkout ราคา หรือสถานะรอบขายจริง

## ข้อจำกัด PR17 ที่ลำดับ 1 แก้แล้ว

PR17 มีรูปปกหนึ่งรูปและ preview markup ใหม่ โดยดึง **style block แรก** ของ Home Terrain
เท่านั้น จึงเป็นฐานทดลอง ไม่ใช่ renderer ของเว็บจริงทั้งหน้า และยังไม่รองรับ Woven Stride
เว็บจริงมี 2 style blocks; block หลังและ body class มีผลต่อธีม ปุ่ม และการเลือกซื้อ
ลำดับ 1 เปลี่ยนเป็นดึงครบทั้งสอง style blocks และ body class ของแต่ละหน้าแล้ว แต่ยังไม่ใช่การเปิดหน้าใหม่บนเว็บจริงหรือรับรอง published snapshot parity

## ขอบเขตระบบที่ควรสร้าง

1. **โครงหน้า / Layout** — เลือกจากแบบที่ NORX รองรับ; เริ่มจากโครงสินค้าปัจจุบัน
   มีภาพหลัก รายละเอียด จุดเด่น แกลเลอรี ตารางไซส์ ส่วนสั่งซื้อ; เปิด/ปิดและจัดลำดับ
   ส่วนเนื้อหาที่อนุญาตได้ ไม่เปิดเขียน HTML/CSS หรือทำ page builder อิสระ
2. **ธีม / Theme** — แยกจากทรงเสื้อและ Layout; เริ่มด้วย Home Terrain (เข้ม/ส้ม)
   และ Woven Stride (ขาว/ดำ/กริดบาง) เก็บเป็น preset ที่มีเวอร์ชัน สีพื้น ตัวอักษร
   สีปุ่ม เส้นขอบ และพื้นผิว เปลี่ยนธีมได้โดยไม่เปลี่ยนรหัสสินค้า/ราคา/ทรง/ไซส์
   โทนรุ่นใหม่เริ่มจาก preset แล้วเพิ่มสีที่ผ่านการตรวจให้อ่านง่าย ไม่บังคับทุก Drop ใช้ส้ม
3. **เนื้อหาเฉพาะรุ่น** — ชื่อ เรื่องราว จุดเด่น ผ้า/ทรงที่ยืนยันแล้ว ภาพปก
   กลุ่มแกลเลอรี คำบรรยายและ alt text; เพิ่ม/แทนที่/ลบ/เรียงรูปได้
   รองรับภาพหลักมือถือแยกเมื่อจำเป็น และจุดโฟกัสภาพ แสดงภาพเต็ม/ครอปตามบทบาท
4. **ตารางไซส์เฉพาะรุ่น** — ไม่ใช้ตารางเดียวกันทั้งร้าน; รองรับคอลัมน์และหน่วย
   ตามข้อมูลจริง รวมคำอธิบายความคลาดเคลื่อน และความต่างของแขนสั้น/แขนยาว
   คำแนะนำวัดเสื้อเป็นข้อมูลเนื้อหา ส่วนรายชื่อไซส์ที่สั่งซื้อได้ยังอิงแคตตาล็อกจริง
5. **ระบบซื้อร่วมกัน** — เมนู ปุ่มหลัก/รอง ลำดับเลือกแบบ-ไซส์-จำนวน ตะกร้า
   การชำระเงิน และความหมายสถานะต้องสม่ำเสมอ เปลี่ยนได้เพียงรูปลักษณ์ที่ธีมกำหนด
   ไม่มีปุ่มซื้อจำลองที่ทำให้ลูกค้าเข้าใจว่าเปิดขายแล้ว

## วิธีแก้หน้าเดิมโดยไม่กระทบออเดอร์

- ผูกหน้า `/home-terrain/` กับ `drop03` และ `/woven-stride/` กับ `drop02` เดิม
  รักษา URL และตัวตนสินค้า ไม่สร้างสินค้าซ้ำเพื่อเปลี่ยนสี/รูป/ข้อความ
- แยกข้อมูลนำเสนอที่เป็นร่าง/เผยแพร่แล้วออกจากราคา ตัวเลือกสินค้า รอบขาย และสถานะออเดอร์
  สินค้า active ต้องแก้ **ร่างเนื้อหาหน้าเว็บ** ได้ แม้ commercial fields ยังถูกป้องกัน
- ฉบับเผยแพร่ต้องเป็น snapshot พร้อม revision: ระหว่างแก้ร่าง ลูกค้ายังเห็นฉบับเดิม
  แก้พร้อมกันต้องเตือน conflict; บันทึกร่างไม่เผยแพร่โดยอัตโนมัติ
- Preview ใช้ข้อมูล snapshot และ renderer/theme version เดียวกับที่จะเผยแพร่จริง
  ดูมือถือ/คอมพิวเตอร์และส่วนท้ายหน้าได้; แก้ข้อมูล/รูป/ธีมแล้วให้ตรวจพรีวิวใหม่
- แสดงสรุปสิ่งที่เปลี่ยนก่อนยืนยันเผยแพร่ และเก็บฉบับก่อนหน้าให้ย้อนคืนได้
  การย้อนเนื้อหาไม่ย้อนออเดอร์/ราคา/รอบขาย รูปที่ฉบับก่อนหน้ายังต้องใช้ห้ามลบเร็วเกินไป
- หน้าแรกมีข้อมูลของตัวเองและการ์ดที่อ้างอิงสินค้าตัวเดิม; รองรับแก้ภาพ/ข้อความ/ลำดับการ์ด
  ใช้ธีมกลาง NORX โดยไม่ล้างธีมหน้าสินค้า การ์ดกดไป URL เดิม
- วิธีเชื่อมข้อมูลกับ hosting จริงยังต้องตรวจ/ตัดสินใจในงานเชื่อมต่อ ให้ SEO มี HTML
  ที่ใช้ได้ ไม่พึ่งรอ JavaScript เปลี่ยนทุกส่วน และมี fallback/rollback ก่อนเปิดใช้งาน
